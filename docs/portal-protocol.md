## 当前网页的真实请求

入口的 `a41.js` 负责加载配置、状态和业务脚本；`a43.js` 实现本地认证。在本地认证分支中，账号使用输入值加配置后缀，**不使用**旁路认证分支的 `,0,`、`,b,` 等账号前缀。当前配置后缀为空。

以下请求是实现依据。登录已进行用户授权的真实请求诊断；注销仅检查了网页实现，未在真实网络上执行。

### 登录

`GET http://10.151.253.10/drcom/login`

| 查询参数 | 值 |
| --- | --- |
| `callback` | `dr1003`，位于所有业务参数之前 |
| `DDDDD` | 用户输入的校园网账号 |
| `upass` | 用户输入的密码 |
| `0MKKey` | `123456` |
| `R1` | `0` |
| `R2` | 空字符串；脚本仅在 MD5 模式置为 `1` |
| `R3` | `1`，校园网服务 |
| `R6` | `0` |
| `para` | `00` |
| `v6ip` | 空字符串 |
| `terminal_type` | `1`，PC |
| `lang` | `en`，业务参数中的第一处 |
| `jsVersion` | `4.2.1` |
| `v` | 用于避开缓存的随机整数，范围 `500..10499`（含两端） |
| `lang` | `en`，通用 JSONP 参数中的第二处 |

参数严格按照上表顺序构建：

```text
callback,DDDDD,upass,0MKKey,R1,R2,R3,R6,para,v6ip,terminal_type,lang=en,jsVersion=4.2.1,v,lang=en
```

两个 `lang=en` 刻意保留，不能使用会去重或重新排序的参数构建方式。`0MKKey` 是网页协议中的固定字段，独立于用户输入的密码。

使用 URL 编码构建参数。不得把完整认证 URL、账号或密码写入应用日志。JSONP 应作为文本取回、校验回调包装后解析 JSON；不得执行服务器返回的 JavaScript。

静态脚本将 `result=1` 或 `result="ok"` 视为请求成功。应用还应通过只读状态接口确认连接结果，不能把任意 HTTP 200 或任意网页响应视为登录成功。

### 注销

`GET http://10.151.253.10/drcom/logout`

当前本地认证分支传入空业务参数，通用 JSONP 请求按 `callback`、`jsVersion`、`v`、`lang=en` 顺序构建。不需要发送账号密码。用户明确点击断开时才执行注销，并再次查询状态确认结果。

### 在线状态

`GET http://10.151.253.10/drcom/chkstatus?callback=dr1003&jsVersion=4.2.1&v=8000&lang=en`

该接口已进行只读请求，返回 JSONP，且当前会话的 `result=1`。页面代码将 `result=1` 解释为在线，`result=0` 解释为离线。网络超时、HTTP 错误、无效 JSONP 和缺少 `result` 应解释为无法确定状态，不能直接等同于已断开。

以自定义回调名称 `campuslinkResearch` 请求时服务器返回 HTTP 400；改为 `dr1003`、`dr1004` 后成功。因此应遵循页面的 `dr` 加数字命名方式；尚未证明服务器所有回调名称规则。

客户端 IPv4 可按页面的兼容顺序从 `v46ip`、`ss5`、`v4ip` 读取，并验证格式。本次三者均存在。页面还支持缺省时将 `ss3` 从十六进制转换为 IPv4，但本次返回没有 `ss3`。MAC 相关字段包括 `ss4`、`olmac`，认证并不要求本工具把它们附加到本地登录请求。`time`、`flow` 虽为数字，但单位和账期语义未在本次核验中确认，不应当作实时网速展示。

## 兼容元信息与页面标记

入口还包含供兼容客户端使用的元信息：

- 登录：端口 `801`，`/eportal/?c=ACSetting&a=Login`，字段 `DDDDD` / `upass`，附加 `url=drappall`。
- 注销：端口 `801`，`/eportal/?c=ACSetting&a=Logout&ver=1.0`，附加 `url=drappall`。
- 查询：端口 `80`，路径 `/`。

上述元信息与当前网页实际调用的 `/drcom/` 分支不同。实现优先遵循已读取的当前业务脚本，不将未经执行的兼容路径宣称为验证成功。

当前在线入口包含 `Dr.COMWebLoginID_1.htm`，但其兼容配置的 `authsuccess` 为 `Dr.COMWebLoginID_3.htm`。因此只匹配 `_3` 会漏判实际在线页面。优先使用结构化的 `chkstatus`，必要时对入口文本的兼容判断必须覆盖实际 `_1` 在线标记。

## 验证范围与后续维护

### v1.0.1 状态检测兼容

应用启动时无条件只读检测，不依赖是否保存账号密码或开启自动连接。运行期间按设置间隔（默认 10 秒）及返回窗口时刷新，在线时显示会话详情而不是登录表单。查询异常保留“状态未知”，不会据此自动提交认证。

实际接口返回声明了 `application/javascript; charset=gbk`，解析前按声明的编码解码。JSONP 仅提取严格 JSON 参数，不执行响应脚本。如果状态接口异常，则只读请求认证根页；仅识别脚本之外唯一的 `<!--Dr.COMWebLoginID_1.htm-->` / `_3` 在线标记或 `_2` 未认证标记，不使用页面中 `authsuccess`、`authfail` 等模板字符串来推断当前状态。无明确标记、冲突标记或网络错误仍作为未知状态处理。

v1.0.1 的状态检测核验确认：没有已保存密码、自动连接关闭时，启动只读检测后直接进入已登录界面，账号密码输入框不存在。该轮没有稳定复现用户截图中的原始解析失败，因此增强了字符编码兼容、JSONP 包装兼容及独立根页状态回退。该轮未执行真实登录或注销。

### v1.0.2 登录请求与响应诊断

本轮用户提供凭据并授权真实登录诊断。旧参数顺序得到 HTTP 203，响应正文为 `Bad request(2)`，因此此前的通用“服务器响应无法识别”提示没有说明真实失败原因。将参数顺序调整为网页顺序后，服务器返回 HTTP 200 JSONP，业务错误为 `error5`、`waitsec < 3`。HTTP 200 表明收到可解析响应，不代表认证成功。

用户随后提供了同一参数顺序、使用 `lang=en` 且返回 `result=1` 的成功抓包。v1.0.2 据此对齐登录参数顺序、`lang=en`、重复的两个语言参数，以及网页使用的 `v=500..10499` 随机数范围。本轮原有在线会话始终保留，没有为了验证登录而注销或断开网络；因此该抓包与协议修正不能替代应用在离线设备上的首次登录验收。

错误日志支持点击“查看响应”。每条错误记录可包含多次请求，例如状态接口失败后再请求认证页的回退链路。详情包含错误代码、请求方法、去掉查询参数的 URL、HTTP 状态码、响应类型、耗时和脱敏响应正文；没有收到 HTTP 响应时单独注明。每次请求的正文最多保留 16 KiB（UTF-8 字节数），超出时截断并提示。正文仅作为纯文本显示，不执行 HTML 或 JavaScript，支持“复制详情”。记录只保留在当前进程内存中，不写入设置或日志文件；主动复制会写入系统剪贴板。
