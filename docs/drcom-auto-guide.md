# Dr.COM 自动识别

开发者：**NingMeng123** · [GitHub](https://github.com/65658dsf)

在“连接方案”搜索 **Dr.COM 自动识别**。此方案会读取当前网络的认证页面、同源静态脚本及可识别的只读配置接口，识别认证方式、接口端口、账号前缀和网络服务。它适合多所学校共用一个入口，也保留按学校核验的专用方案。

## 使用

1. 先连接校园 Wi-Fi 或有线网络，选择“Dr.COM 自动识别 · 通用方案”。
2. 网络服务先保持“自动”，使用页面默认服务；也可选择校园网、电信、移动或联通。完整账号模式不追加运营商后缀。
3. 认证页、认证端口可留空，账号前缀保持 `auto`。填写账号密码后连接。
4. 如果当前网络不返回发现入口，填写浏览器显示的认证页，例如 `http://10.0.0.1/`。若页面没有明确端口或前缀，可根据学校实际页面补充；`none` 表示无账号前缀，`,0,` 表示明确使用此前缀。

“完整账号”只控制运营商后缀；协议要求的 `,0,` 等终端前缀仍由识别结果处理。端口和前缀的手动值用于解决缺失信息，不会关闭对加密、验证码或不支持分支的检查。

识别过程不提交账号密码、不尝试登录、不扫描端口，也不轮流尝试不同前缀。登录与注销完成后还会独立查询状态；无法确认在线或离线时显示错误，不把未知状态当作断网自动重试登录。

## 支持范围

| 认证方式 | 登录接口 | 适用条件 |
| --- | --- | --- |
| Dr.COM Web 本地认证 | `/drcom/login` | 可确定本地认证分支、原密码模式及服务值 |
| 旧版 ePortal | `/eportal/?c=Portal&a=login` | 可确定旧版接口、端口、前缀及后缀 |
| 新版 ePortal | `/eportal/portal/login` | 可确定新版接口、端口、账号格式及设备上下文 |

自动识别的目标是覆盖有明确配置证据的常见网页认证，并不意味着所有 Dr.COM 部署都能自动登录。AES、XOR/页面参数加密、MD5、验证码、特殊无感知前缀、任意运行时代码和锐捷 802.1X 客户端认证不在此通用流程范围内；识别到这些情况会明确停止。参数不完整或矛盾时，应使用已核验的学校方案或补充实际认证页信息。

## 为什么不只抓 801 和 `,0,`

认证页的 `authloginport`、`authloginpath` 可能是旧客户端兼容信息，不代表当前网页实际请求。广州理工学院公开页面的兼容端口为 801，而脚本 `epHTTPPort` 为 803；南京邮电大学脚本使用 HTTPS 配置。这些页面也可能开启额外加密，因此端口识别成功仍不足以确认可登录。

`account_prefix` 通常是开关而不是前缀本身。普通电脑分支启用时使用 `,0,`，但移动端和特殊无感知模式会不同。运营商选项有时是账号后缀，有时映射 `R3`；通用方案按明确分支处理，不将所有选项都附加到账号。

## 本地数据与维护

每次操作重新读取当前网络参数，防止换网后复用旧设备 IP 或旧端口。认证成功后探测地址通常不再跳转，应用会在进程内保留已确认的门户来源和页面路径用于后续查询与注销；新发现的门户优先，不缓存设备查询参数。只保存用户填写的覆盖项和方案定义；临时页面、脚本、配置响应及设备信息不写入方案文件。可从卡片导出 JSON，或使用 [通用示例](../examples/drcom-auto.example.json)。

自动化验证使用本地模拟门户，覆盖多端口、账号前缀、服务选择、配置冲突、额外加密、只读发现、未知状态和凭据脱敏；不能替代每所学校的真实校内验收。
